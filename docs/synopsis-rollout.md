# あらすじ欄：データ仕様と本番反映

## 仕様

- 書籍ドキュメントの任意フィールド `synopsis`（500文字以内）と `synopsisSourceUrl`（HTTPS URL）を使う。
- あらすじは出版元・図書館などの公開書誌で作品を照合し、紹介文を短く独自の表現で要約する。公式文の長文転載・結末の推測は避ける。
- 両フィールドは同一コマンドで登録・訂正する。片方だけの登録は禁止。
- 読書状態・感想・本人の発言・★評価・`notes` は変更しない。
- アプリの「本の詳細」では、あらすじがある場合だけ表紙の下に表示し、出典へのリンクを付ける。未登録の本は表示しない。
- データは家族専用の Firestore にだけ保存する。公開 GitHub には実本棚の書名・あらすじ一覧やコマンドJSONを置かない。

## 実装の切り分け

1. 公開リポジトリでアプリ・共通 `gas/Queue.gs` のテストを通し、通常のコードレビュー／マージを行う。
2. 非公開の実運用 Apps Script には、公開版の追加バリデーションを同期する。**実運用側の `WRITE_ENABLED` やトリガー・秘密設定は維持**し、公開ファイルの初期値 `false` で上書きしない。
3. Hosting は `firebase deploy --only hosting --project kodomo-reading-shelf-87f11` で別途反映する。Firestore Rules の変更は不要。
4. 認証済み Firestore 現在値と版を確認し、プライベートな更新キューに `catalog.audit`（各エントリに `id`, `expectedTitle`, `patch`, `expected`）を小分けで登録。`patch` は `synopsis` と `synopsisSourceUrl` だけ、`expected` は両フィールドの現在値を指定する。
5. GAS が `APPLIED/COMMIT_OK` と記録しても、それだけで完了とせず、永続マーカーと Firestore 値を独立に照合する。`REVIEW`/`CONFLICT`/不明状態を新しいIDで再送しない。
6. 実際の家族アカウントで「本の詳細」の表示・出典リンクを確認する。

## 内容の品質基準

- 作品名だけでなく、著者・版・可能ならISBNで公式ページとの一致を確認する。
- 1冊あたり100〜250文字程度を目安に、登場人物、物語の発端、主要な課題を簡潔に記す。
- 作品の結末、未確認の登場人物・設定、本人の感想を混ぜない。
- 確認できない作品は未登録にし、出典が見つかるまで保留する。
