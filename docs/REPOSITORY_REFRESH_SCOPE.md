# よんでね｜公開リポジトリ履歴刷新：移植範囲・受入条件

更新：2026-11-16。これは **現行リポジトリを監査・整理するための計画**。本番データ・サービスを移行する指示ではない。

公開データ・第三者素材の監査結果：[公開コンテンツ監査](PUBLIC_CONTENT_AUDIT.md)。

## 真の目的

公開GitHubの新たな初期状態を、**個人データ・非公開資料・未許諾著作物を含まない、読みやすく再現可能なソース**だけで構成する。単にコミット数を減らすことは目的ではない。

監査基準は公開GitHubへの収録範囲。認証済み「本の森」が実行時に読書感想の一部をLLMへ送る設計は既存の承認済み機能であり、この整理で無断変更しない。

## 最新版から持ち込むもの

移植元は、開発中のPRをすべて確定した時点の**固定した `main` コミット**。本書作成時の監査基準は `c4f6a1d418` だったが、移植時に再取得する。

- **PWA・Firestore Rules・テスト**：`reading-shelf-firebase/`。Web画面、会話、認証、読み聞かせ、感想、★、推薦、PWAを保護する。
- **正式Workerとテスト**：`cloudflare/forest-ai/`。名前・エントリ・共有NPCレジストリを維持。
- **GAS共通コードとテスト**：`gas/Queue.gs`、`gas/queue.test.mjs`。実際の非公開 `Code.gs` と本番 `WRITE_ENABLED` は持ち込まない。
- **必要なビルド・監査スクリプト**：`scripts/check-public-boundary.mjs`、音声実験室の生成元、現在利用する描画検証ツール。
- **CIと公開開発資料**：`.github/workflows/`、`.gitignore`、`README.md`、最新のデプロイ手順とNPC登録手順。

`forest-voice-lab.html` は生成済みの配信対象なので、生成元と生成結果の一致をCIで検証して保持する。

## 持ち込まないもの

- **Gitの過去履歴、旧ブランチ、旧PR/Issue、ActionsログやArtifacts、過去の公開レビュー・コメント**。新規リポジトリは旧リポジトリからfork・mirror・履歴付きcloneで作らず、監査済みファイルだけで初回コミットを作る。
- **家族・子どものUID、書籍IDの実値、感想原文、星や読了履歴、更新キュー実コマンド、非公開SheetsのID・実データ、非公開キャラ台帳、キャラクター画像原本、秘密鍵、OAuthトークン、GASの本番設定**。
- **古い移行計画や終了済み一回限りの監査スクリプト**は、現在の本番運用・再現性に必要かを判定してから削除。候補：`docs/PRIVATE_REPO_RETIREMENT.md`、`gas/STAGE_F_CUTOVER_AUDIT.md`、`gas/STAGE_I_RECOVERY_HANDOFF.md`、`gas/Production*Probe.gs` と対応テスト。
- **過去バージョン固有の設計メモ**は、現行仕様に必要な要点だけに統合する。候補：`docs/book-forest-conversation-director.md`、`docs/book-forest-shared-memory.md`、`docs/book-forest-thought-engine-v6.md`、`docs/book-forest-voice-fidelity-v8.md` など。現在のコードを説明する新しい資料に置き換える。削除する前に現行コードと参照リンクを確認。
- 上記以外でもライセンス・出自が不明な第三者画像、絵本本文、未検証の実データのサンプルは含めない。

**対策済み（新コード）**：非公開Driveの画像マニフェストの実ファイルIDを公開コードから削除し、所有者のGoogle認証後にフォルダ名・ファイル名から発見する方式へ変更。実際のファイルIDは新規リポジトリに移植しない。ただし旧リポジトリのGit履歴には残るため、旧リポジトリの名称切替と削除を完了するまで公開履歴の露出は解消しない。Hostingへの新版配信は別工程。

## 移行の安全条件

1. 継続中の機能開発とCIを完了し、対象 `main` SHAを固定。未統合PRの必要な変更を判断し、誤って失わない。
2. 現行ファイルの公開境界チェックに加え、**全ブランチ・過去コミット・GitHub上の付属物**の混入有無を確認。発見した秘密情報は履歴削除だけで対処せず、必要なら認証情報を失効・再発行する。
3. 著作物について、公開GitHubに収録されるファイル単位で権利・ライセンス・改変経路を確認する。
4. 監査済みのファイルを`git archive`等で**履歴抜き**に抽出し、不要な歴史文書等を除外。新規 `yondene-public2` に**単一の初期コミット**として登録。旧コミットの親を持たせない。
5. 新規リポジトリで公開境界チェック、CI、Workerのドライラン、配信物の差分、アプリ・Rulesの回帰を確認。**新旧リポジトリを検証するために本番のFirestore・Hosting・Worker・GASを再作成しない。**
6. GitHub App権限、CI、外部参照、デプロイ手順、必要なリポジトリ設定を確認。**GitHubのリポジトリIDは変わる**ため、名前が同じになっても接続が自動継承されるとはみなさない。
7. 完全な切替確認前には旧 `yondene-public` を削除しない。旧リポジトリを安全な退避名にして新リポジトリを最終名に変更し、リンクと連携を確認してから旧リポジトリ削除を判断する。

## 本工程の対象外

現在のFirestoreデータ・家族権限・GASの単一writerと非公開Sheets・Worker/Hostingの本番設定、課金設定は変更しない。公開GASの安全初期値を実運用GASへコピーしない。

## 判定

移行元の最終スナップショットが監査済み、保護すべき機能を新リポジトリで再現できる、公開禁止物を含まない、必要なGitHub連携が復旧した、という**結果**で移行の可否を判断する。コミット数やテスト件数そのものは合格条件ではない。
