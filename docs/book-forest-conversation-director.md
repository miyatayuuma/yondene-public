# 本の森 — 会話ディレクター v0.3（人物視点・出典付き発話／ふたごの掛け合い）

## ねらい

森で NPC に話しかけるたび、同じあいさつを繰り返すのではなく、読書の進み具合、以前の会話、本人の感想、相手の性格によって話題が変わる。子どもの操作は短い選択肢だけ。**現時点ではランタイム LLM は使用しない**ため、会話ごとの推論料金・トークン消費はない。

v0.2 は、物語記憶の第三者視点の文章を NPC の台詞へ直接差し込む旧方式を廃止した。非公開「物語記憶」の正式な memoryId に紐づけ、キャラ本人の視点で個別に書かれた `approved` の短い発話だけを使用する。記憶と台詞のデータは分離し、同じ出来事を別キャラが違う視点で話せるようにする。

## 情報源と秘匿

- 本棚と `childReflections` の現在値は Firestore が正本。認証済み owner のブラウザが既存の Firestore 権限で読み取り、書き込みはしない。
- 作品の出来事は非公開「物語記憶」タブ（出典があり `approved` の短い事実のみ）。書名から読了を推測せず、Firestore の `book.id` と `status:'read'` で許可する。
- 台詞は非公開「会話台本」タブ。本文は原作の引用ではなく独自の短文。`approval:'approved'` のみ使用し、キャラ別の台詞、無言の猫の所作、感想への反応、他キャラへの引き継ぎを記録する。
- 公開 GitHub に実際の bookId、台詞本文、非公開 Sheet ID、個人の感想、Google アクセストークンを置かない。コードと架空 ID のテストのみ公開する。
- Sheets の内容は Google Drive で認可された所有者のブラウザだけが HTTPS の Sheets API で読み取る。既存画像と同様、会話台本と物語記憶は所有者・家族で分離した端末キャッシュに保存し、ログアウトと「森の素材を更新」で消去できる。**本文の全件が所有者の端末へ渡る設計**であり、信頼できない端末での利用は避ける。感想本文はキャッシュしない。
- 会話の進行状態は端末の `localStorage` に訪問回数、承認済み台本・記憶・感想の不透明な識別子、既読本IDの集合、直前の引継ぎ先を保存する。新たな読了を検出するための既読本IDも含まれるが、感想原文、会話本文、発話ログは保存しない。家族やユーザーが変われば別のキーになり、明示的なログアウト時に削除する。

## 話題選択の仕様

1. 本棚の最新スナップショットで `read` の本だけを許可。未承認・未出典・結末ネタバレの記憶は排除。
2. 初対面はあいさつを優先。初めての相手に、前の NPC からの引き継ぎがあっても、最初はあいさつから始める。選択肢で「本の話」へ続けられる。
3. すでに会った相手なら、NPC からの引き継ぎを優先し、**元のエピソード ID** を渡す。後から未読状態に戻った本の事実は除外する。
4. まだ使っていない正式な本人感想・保護者要約を優先する。本人原文と保護者要約は語り分ける。取り消された感想は既存コレクションに存在しないため表示しない。
5. 前回訪問以降に `read` へ変わった本に紐づく承認済みの個別発話を優先。次に未使用の発話を選ぶが、物語の話が続けば日常会話を挟み、同じ話題ばかりにならないようにする。
6. 承認済みの個別発話がない記憶は、**元の説明文を代用しない**。安全な日常台詞などへ切り替える。データ取得に失敗しても探索自体は継続できる。

9 種類の会話 ID に、初対面9、日常18、物語ひな型9、感想9、会話の引継ぎ9の **旧54件**がある。v0.2 では旧物語ひな型9件を実行時に除外し、非公開台帳に追記した **記憶ID別・人物別の71件**を採用する。元の34冊／121件の物語記憶は削除しない。人物別発話がまだない記憶もあり、その場合は説明文に戻さない。表示上の NPC は10体で、ふたご2体は同じ会話セッションを共有する。

## ふたご専用の会話・移動（v0.3）

- **二人で一組**。現行の別々の立ち絵とタップ可能範囲を維持し、歩行目標・歩行速度・停止を共有する。片方に接近した時や話しかけた時は両方が立ち止まる。スプライトは非公開の共通画像を再利用する。
- 話しかけるたびに、非公開「ふたご名前」タブに記録された承認済みの名前ペアから**前回とは異なる組**を順に選ぶ。初めの一声は「ふたご」と表示し、二人がそれぞれ名乗った後は各ターンを名前付きで表示する。名前の付け替えは会話中には起こらない。
- 非公開「ふたご会話」タブの承認済みシーンを短い発話単位で自動進行。画面に直近4発話を残し、名前ラベルと発話本文を別要素に分ける。本文には `「」` を使わない。
- 通常は二人が森での小さな発見を交互に話す。少数のシーンで子どもに話しかけ、返答の選択肢を出す。無反応でも一定時間後に次の発話へ進む。会話を閉じるか森を退出すればタイマーを止め、タブをバックグラウンドへ移した場合は自動進行を一時停止する。
- 原作中の出来事を扱うシーンは、対応する**承認済み `memoryId` と Firestore の現在の `read` 状態**を必須にする。人物の台詞として書かれた行のみ使い、物語の説明文を差し込まない。会話中に既読状態が取り消された場合も後続行を表示しない。
- 名前と台詞本文はすべて非公開台帳に保持する。公開側の `book-forest-twins.mjs` はシーンの検証、二話者の順序、分岐、速度、文脈ゲートのみを扱う。実行時LLM・会話本文のクラウド保存・継続課金は追加しない。

`ふたご名前` の列：`schemaVersion | pairId | firstName | secondName | approval`

`ふたご会話` の列：`schemaVersion | sceneId | sequence | speakerSlot | text | bookId | memoryId | choicesJson | approval`

`speakerSlot=0` は冒頭のグループ名、`1` と `2` は個人名。`{firstName}` と `{secondName}` を承認済みの名前で置換する。`bookId` と `memoryId` は物語に基づくシーンのみ設定する。選択肢の JSON は架空テスト用例に限定して公開し、本番の台詞をコードへ複製しない。

## 非公開「会話台本」の列

`schemaVersion | cueId | npcId | kind | bookId | memoryId | fromNpc | text | choicesJson | approval`

`kind`: `meet`, `ambient`, `story`, `reflection`, `relay`。

`story` は **正しい `memoryId` を必須**とし、`text` にそのキャラ向けの承認済み発話をそのまま記載する。`{memory}` の汎用置換は禁止。`reflection` は `{reflection}` を使えるが、本人原文と保護者要約の区別を保つ。`reflection` の `bookId` は対象本を特定する（全本の子ども感想を一括取得しない）。`relay` は直前の NPC を `fromNpc` に指定し、前回の記憶IDに対応する**受け手キャラの承認済み発話**だけを `{memory}` に挿入する。受け手の発話がなければ未承認の説明文に戻さず、同じ出来事を話せない相手への引き継ぎ選択肢を隠す。

私的な会話台本は元データを上書きせず行追加している。v0.3 ではふたごの二つのタブを追加し、会話キャッシュを `v3` に更新して初回だけ非公開台帳を再取得する。その後は従来どおり端末に保存する。旧 `v1` / `v2` キャッシュは素材更新・ログアウト時に削除する。

## AI発話の作成・品質ゲート

- 公開コードの `book-forest-dialogue-generation.mjs` に、承認済み根拠・キャラ設定から生成タスクを組み立て、生成候補を検査し、非公開台帳用の **draft 行**へ変換する契約を追加した。
- 制約チェックは文字数、出典有無、第三者視点の自己紹介、説明文丸写し、ねこの人語など。これだけで意味上の矛盾は検出できないため、**原作との整合性・キャラらしさは別途監修**する。
- 公開GitHubに実際の台本・読書記録・非公開の書籍IDを置かない。候補の保存先は非公開台帳で、`approved` への昇格は明示的な編集判断とする。
- このモジュールはAPI資格情報や生成サービスを持たない。**現在のゲームにリアルタイム生成・会話履歴のクラウド永続化はまだない**。将来の生成サービスはサーバー側認証・秘密鍵管理・無料枠/費用上限を満たした後に接続する。

`choicesJson` の例（架空・実データなし）：

```json
[{"id":"another","label":"ほかの話を聞く"},{"id":"visit","label":"別の子にも聞く","text":"向こうにも行ってみよう。","relayTo":"cat"}]
```

## 動作・費用

- Forest 起動時に台帳発見のため Drive API 1回、読み込みのため Sheets API 1回。2回目以降は端末キャッシュを使う。
- 登場人物に話しかけた時、必要な感想は対象本ごとに最大5件だけ Firestore から読む。メモリと会話台本選択は端末内処理であり、トークン消費0。
- 会話が好みに合わない、記憶が偏る場合は、別の台本を追加・承認する。表情や行動は原作の具体的な記述と区別して独自演出として監修する。
- 当面は「設定 → 本の森 → 森の素材を更新」で非公開台本を再取得する。Sheets API が対象 Firebase プロジェクトで未有効の場合、ユーザーによる Google Cloud Console の有効化が必要。Google アカウント承認も初回だけ必要になる可能性がある。
