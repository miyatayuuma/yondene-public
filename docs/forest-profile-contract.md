# 本の森 人物設定契約 v2（Issue #10）

## 原因と採用構造

旧読込は人物セルを260字で切り、生成ガイドも項目別に再短縮していた。
一人称の括弧注記を捨て、人物の確認状態だけで話し方を採用し、端末キャッシュには有効期限がなかった。

編集正本は非公開Sheetsの「人物設定」。横長の人物表を連結せず、NPC×意味のある項目を1行にする。

| 列 | 意味 |
| --- | --- |
| NPC ID | 公開レジストリの会話ID。追加の表示actorは同じ会話IDを使う |
| 項目 | 人物像、価値観、動機、関係性、行動、反応、一人称、呼称、口調、語尾、癖の頻度、言い回し、感情変化、禁止・注意 |
| 内容 | その項目の編集済み内容。未照合・巻・条件の注記を含めて保持 |
| 根拠区分 | 原作本文／公式資料／二次資料／編集解釈／ゲーム演出 |
| 根拠資料ID | 「根拠資料」のIDを参照。原作本文・公式資料・二次資料は必須 |
| 適用範囲 | 巻、年齢、時期、利用条件。別巻へ無条件に一般化しない |
| 監修状態 | 確認済／暫定採用。解釈と演出を原作確認済にはしない |
| 設定版 | 同一NPCで一致する編集上の版名 |

表示名・作品・版・監修メモも同じ表に保存するが、人物プロンプトの指示として自動注入しない。
モデルに必要な条件・未確認事項は各項目の内容・適用範囲へ明記する。
同じ人物・項目の重複、出典不明、版の不一致は編集エラーとして拒否し、片方を勝手に採用しない。
暫定採用は演技に使えるが、原作確定として語らせない。確認済の資料だけを参照していても、解釈が原作事実に昇格するわけではない。
混合確度の内容は保守的な区分に置き、本文内の留保を保持する。項目ごとの原文照合は別の監修作業。

「根拠資料」は従来の原作資料と物語資料を同じ10列へ対応づける。
資料ID、作品・版、対象キャラID、事実／描写の要点、根拠の種別、章・ページ等、出典URL、確認日、確認状態、メモを保持する。
日付があるだけの物語資料を原作照合済に変更しない。URLの一致だけでは異なる要点の行を削除しない。
実行時は選択された人物の資料ID・種別・確認状態のみを渡し、原作資料本文を重複した長いプロンプトにしない。
物語記憶の読了・承認・出典資格判定は従来どおり。完成台本は通常生成へ注入しない。

## 入力・版・鮮度

全項目の内容と確度・適用範囲を共通ガイドへ渡す。欄の途中で切らない。
1項目1200字、ガイド全体6000字を超える場合は明示的な編集エラー。
優先順は価値観・動機・関係性・行動を核とし、話し方は表現として扱う。
ねこの人格も同じ経路を使い、特殊化するのは既存の非発話出力形式だけ。

編集版とは別に、全項目・注記・採用状態・参照資料の種別と確認状態から内容指紋を作る。
これは診断用の非暗号学的指紋であり、認証・完全性署名ではない。
`npc.profileSchemaVersion/profileVersion/profileRevision` とガイド本文をWorkerへ送る。
Workerは使用したprofileRevisionを返し、端末は要求した版と一致しなければ結果を採用しない。
端末ログには版と指紋、エクスポートにはappBuildも残す。人物本文・出典本文を公開診断へ追加しない。

「人物設定・会話を更新」は認証してその場で再取得する。画像の再取得は不要。
取得中のログアウト・家族変更時は採用せず、キャッシュ書込後の所有者変更も消去する。
通常キャッシュはUID・家族で分離し、有効期限1時間。期限切れ・旧schemaは再読込し、失敗時に古い人物設定でAIを起動しない。
会話開始時に取得した設定を、その短い会話内のスナップショットとして使う。

## 実生成検証

`node scripts/build-forest-persona-probe.mjs` は共通パーサー・promptFor・Workerの
forestGenerationInput/readCompletionを束ねた `gas/ForestPersonaProbe.gs` を作る。
非公開台帳の検証GASファイルをこの内容へ置換する。同名の旧関数と二重に追加しない。
通常本棚writerのGAS、Script Propertiesの認証値、トリガーには触れない。

既存の検証用Script Propertiesを使い、PENDINGだけを最大3件／実行・60試行／日で処理する。
既存ERRORやDRAFTを変更せず、一意の新requestIdで架空場面を試す。
出力に加え、編集版・内容指紋・実際のWorkerモデル入力JSON・取得時刻・出力形式検証を非公開結果へ保存する。
生成品質の採点は空欄のまま。形式PASSは人物らしさの合格ではない。
プローブは本番と同じ人物入力・モデル設定・出力検証を使うが、本棚、感想、話題選定、認証、ブラウザ描画の統合試験を代替しない。

## 切替と撤去の条件

1. 新表への本文・根拠・注記の移行を原表と照合する。
2. 最新mainから正式Workerを明示して配信し、/healthの構成・protocolRevision・registryRevisionを確認する。
3. Firebase Hostingだけを正式プロジェクトへ配信し、アプリ版を確認する。Firestore Rulesを配信しない。
4. 新検証GASを導入し、複数NPCの実生成・保存、設定変更→再読込→版変更を確認する。
5. 稼働中のHostingとGASに旧参照がないことを確認してから「キャラ設定」「話し方」「原作資料」「物語資料」を退役する。
   旧資料は非公開保存版で保全する。移行先の検証を済ませる前に旧タブを消さない。

実生成、配信、旧タブ撤去が未実施ならIssue #10は開いたままにする。
実データ・保存版URL・台帳ID・APIキー・実キュー・生成ログは公開リポジトリへ追加しない。
