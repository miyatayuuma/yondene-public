# 本の森 — 思考の種エンジン v6

## 目的

森の誰に話しかけても、読了済みの物語の具体的な出来事を起点に、NPCごとに違う考え方に触れられるようにする。
NPCを決まった順序で訪れる必要はない。新しい本を読んだ、未読に戻したなどの正本情報は毎回照合する。

## 入力と保護

- 非公開の会話スプレッドシートの `思考の種` タブを、所有者の Google OAuth で読む。
- `種ID`、`書籍ID`、`物語記憶ID`、根拠のある事実、問い、対立する見方、`利用状態` をヘッダー名で抽出する。実際の行と ID は公開リポジトリに含めない。
- `使用可`、出典 URL、許容ネタバレ、承認済み物語記憶、**現在 Firestore で既読の書籍**という条件を全て満たす種だけが候補になる。
- LLM には題名と短い公開事実、問い・対立する見方、NPC の哲学上の立場だけを渡す。書籍 ID、物語記憶 ID、家族 ID、子どもの感想本文は渡さない。
- 同期キャッシュは既存と同様にログイン中の所有者＋家族単位。初回 v6 は新しいキャッシュとして Google Drive から再取得する。

## 日替わり対話

1. 日本時間の日付単位で「今日の問い」を1件確定。使用回数が少ないものと直近7件に現れないものを優先。
2. 今日最初に訪れた NPC から提示できる。話しかけた順番による正解ルートは作らない。
3. 同じ種を、NPC 固有の哲学軸（自立と信頼／慎重さと冒険／工夫と誠実さ等）で再解釈する。原作に存在しない思想を登場人物の設定上の史実として断定しない。
4. 前の NPC と今日の問いを共有し、選択された短い選択肢を次の会話へのヒントとして使う。ただしその選択は子どもの信念を意味せず、別 NPC が「立ち聞きした」とは言わない。
5. 同じ NPC には1日2回までAI生成。再訪は問いを一歩掘り下げ、3回目以降は承認済みの短い別れの言葉を表示する。
6. 最初のAI呼び出しで冒頭の一言と返答候補2件を**一括生成**。選択後の返答を最大2回まで生成する。旧来のセッション3回・一日のAPI上限は維持。
7. 生成形式が壊れた場合や通信失敗の場合は、既存の承認済み台本へ安全に戻す。

ねこの身振り、双子の承認済み自動ラリー、子どもの感想を引用する台本は従来どおり生成AIに送らない。

## 使用履歴

- 端末内に `selected`（モデル呼び出し対象に選んだ）と `displayed`（実際に画面へ表示した）を別々に保存。
- 自動生成されたが閉じられた・通信エラーになった内容を `displayed` として数えない。
- 所有者画面の「思考の種の利用回数を記録」ボタンから、必要時に `種の使用履歴` に追記できる。
- **追記時だけ** Google `spreadsheets` 書き込み権限の同意が必要。通常の森の探索では取得しない。
- 書き込み前後にイベント ID を読み、既存イベントを二重記録しない。通信異常時の自動リトライはしない。
- 履歴イベントには匿名の種ID・NPC・日付・生成版のみ。子どもの発言、UID、生成台詞を入れない。
- スプレッドシート側の選抜回数・実表示回数は既存 `COUNTIFS` 数式で増える。

## 限界と受入手順

1. コード上の模擬データテストでは毎日テーマ固定、読書状態の剥奪、違う哲学、再訪、表示記録、同期時の重複回避を検証。
2. デプロイ後、端末で「森の素材を更新」を実行して v6 の `思考の種` タブを読み込む。
3. 既読に紐づくテーマで会話できることを複数 NPC で確認。キャラらしさ、具体的エピソード、無意味な相づち・説明口調を人が評価する。
4. 「思考の種の利用回数を記録」で Google の追加権限を承認し、非公開台帳で実表示回数が増えることを照合する。

この段階では実際のAIの台詞品質・本番 Google OAuth 書き込み権限・スマートフォンの実機表示は未受入。
Cloudflare Worker の既存本番設定は変更しない。Firestore の書籍データも更新しない。
