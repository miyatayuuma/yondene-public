# 本の森：本番経路の統合会話検証

`node scripts/check-forest-conversation.mjs` は、本番と同じ
`createForestDialogueDirector` → `createForestLiveDialogueDirector` →
`promptFor` → `forestGenerationInput` → `readCompletion` →
`validateLiveForestOutput` → `onDisplayed` を実行する。
選択するのは実際に最終表示されたボタンであり、続きのプロンプトを別実装で組み立てない。
`onDisplayed` は本番UIが文章を描画した直後に呼ぶものと同じフック。
時計、ストレージ、データ読取、モデル通信だけを差し替える。

## 実行と境界

```sh
# 合成資料・模擬モデル出力。API通信なし。技術的な状態遷移を確認する。
node scripts/check-forest-conversation.mjs

# 同じ条件を別checkoutの実装で実行する。mainなどの動く参照ではなくSHAで固定する。
node scripts/check-forest-conversation.mjs --source /path/to/baseline-checkout

# 認証済み経路で取得し、リポジトリ外に準備した非公開の読取スナップショット。
node scripts/check-forest-conversation.mjs --input /path/outside/repo/scenario.json

# 同じ経路で実Gemma。既存の検証用アカウントの環境変数を使用する。
# CLOUDFLARE_AI_TEST_TOKEN / CLOUDFLARE_AI_TEST_ACCOUNT_ID
node scripts/check-forest-conversation.mjs --model --input /path/outside/repo/scenario.json
```

入力は `books`、`catalog`、`characterProfiles`、`reflections`、`clock`、
任意の `cues` / `twinNames` / `twinScenes` / `storage` / `visits`。人物設定は本番パーサーで変換したv2形式。
`visits` は `[{characterId, choices:[0,0]}]` のように提示選択肢の位置、または正確なラベルを指定する。
選べないラベルは失敗する。会話が先に終了した場合はそこで止まる。
1シナリオ40回、1訪問3回まで。暗黙の再試行やFirestore・Sheetsへの書込はない。

既定の標準出力は件数、公開NPC ID、版、指紋、検証段階だけ。
`--trace-output /outside/repository/trace.json` を明示した場合のみ、
入力、モデルの生出力、検証後出力、最終フレーム、履歴を保存する。
**このファイルには人物設定・実感想が含まれ得る。公開リポジトリ内への保存を拒否する。**
Git履歴・PR・CIのログにも転記しない。

本棚ミラーを現在値として使う場合は2時間以内の `snapshotAt` が必要。
過去の読取スナップショットの再現は `provenance:'historical-readonly-mirror'` とその取得時刻の
`clock` を明示する。これは過去条件の検証であり、現在のFirestoreの確認ではない。
`qualityAccepted:false` は常に残す。形式・状態遷移の成功から人物らしさを自動認定しない。

## 責務と今回確認した修正

| 対象 | 確認した問題・責務 | 対応 |
|---|---|---|
| 話題選定 | 使用済み記憶の減点50が永久に残り、通常点90が雑談70を下回る | 表示した直近訪問による減点に変更。会話を挟むと薄れ、同じ本を永久に禁止しない |
| 訪問履歴 | 生成開始だけで初対面・記憶の使用が消費される | 通常AIの訪問・使用確定を最初の表示へ移す。日次文脈も表示前はプレビューする |
| 感想の返答 | `reviewSpotlight` の第一声指示が `mode=reply` より優先される | 直前の選択への応答・終了を優先する |
| 現在の場所 | 実Gemmaの初対面で町の原作設定が現在の場面へ混入 | 全NPCに現在の場所と確認できる同席者を明示し、人物同士の関係と同席を区別 |
| 終了時の応答 | 作戦を教えると約束したまま、次の返答が別れだけになる例を再現 | 最終ターンでも先に選択への具体的な答えを返す共通契約に変更 |
| 原作記憶 | 返答の事実取得が日次選定とのID一致に依存していた | 開始時に確認した事実を会話中保持。各返答前に既読・資料の資格を再確認 |
| 感想撤回 | 本の既読だけを再確認し、感想本文の現存は再確認していなかった | 返答前に現存する引用・帰属を再読取。アプリの読取Promiseは実行中のみ共有 |
| 失敗後の操作 | 実Gemma検証で、生成した子どもの選択と無関係な原作の台本へ戻る例を再現 | 生成返答の失敗時は台本の別の話へ進めず、その場で短く終了。最初から台本を使う縮退は有限の往復に制限 |
| 未知植物の摂取 | JSONが正しくても危険な選択肢が通る | 共通モデル契約とWorker・ブラウザ共通の高確度パターン検証を追加 |

通常雑談の `catalog:[]` は維持する。基底ディレクターが初対面・物語・雑談・引継ぎを選び、
感想は雑談枠を置換する。日次モジュールが雑談に別の原作記憶を重ねると、この優先順位が崩れる。
訪問回数・別NPC・選択履歴は引き続き日次文脈から渡す。物語枠では確認済み事実を直接渡す。

安全検証は高確度の文字パターンであり、全ての意味的危険や原作逸脱を判定するものではない。
未知植物を提示した文脈・モデル自身の文と、返答候補を組み合わせて検証する。
通常のパン等の食事や、摂取を断る表現の対照ケースを保持する。

## 既存GASキューからの実モデル検証

文脈モードI列に `integrated-synthetic` または `integrated-mirror` を指定する。
1行は1回のNPC訪問（最大3モデル呼出し）。L列は `[0,0]` のように提示された選択肢の位置を指定し、省略時は先頭を2回選ぶ。
K列に状態が保存された先行requestIdを指定すると、表示後の訪問・話題・感想履歴をそのまま引き継ぐ。
生成失敗を含む結果でも保存済みの終了状態は利用できる。結果のない失敗IDは参照できず、ERRORを再投入しない。
既存キュー・結果の28列を再利用し、人物設定・モデル入力・生出力・検証・最終表示・状態は非公開の結果P列に保存する。
単発の `continuation` と異なり、本番ディレクターが会話と話題を選ぶ。

`integrated-synthetic` は非公開人物設定だけを読み、実本棚・感想は使用しない。
`integrated-mirror` は従来と同じ2時間の鮮度・既読・感想帰属検証を通した読取専用ミラーを使う。
通常writer・トリガー・認証情報は変更しない。1実行3回の上限と冪等性を維持し、検証GAS固有の1日76回制限は撤廃。API提供元の制限はそのままで、結果不明の自動再試行はしない。

GASの `UrlFetchApp` は同期通信のため、ブラウザのAbortController・タイマーだけを差し替える。
11秒を超えたAPI応答は受理せず、ブラウザの締切後と同様に縮退する。
GAS自体が通信を中断できるとの主張はしない。DOM描画・Firebase認証・実機レイテンシの受入は別に行う。


## 今回の実生成・配信受入記録

実Gemmaで通常11 NPC・22訪問を実行し、53回のモデル呼出しに対する入力・出力・最終表示・履歴を非公開に保存した。
5訪問は生成失敗を含むため、会話全体が成功したとは扱わない。
別に未知植物の架空場面4件を実生成した。長い記録がセル上限で保存できなかった1訪問もあり、受入成功から除外した。
記録圧縮後は、必要な生成履歴と各ターンの入力を保持して保存できた。
元の失敗行は削除・再投入せず、対照ケースは別IDで明示した。
人物設定・感想・入力全文・実キューIDはここへ転載しない。

| 体験 | 実測と残る限界 |
|---|---|
| 初対面・複数NPC | 11人を同じ保存状態の系列で訪問し、初対面の第一声から選択・短い終了を確認。人物らしさの強さにはばらつきがある |
| 再訪・原作記憶 | 同じ先行状態の比較で、今の場面として再演する出力から過去を振り返る出力へ変化。ただし現在地の言葉や確認済み事実以外の補足まで、意味的に検証できる仕組みではない |
| 感想・継続 | 本番ディレクターが既読本の実感想を選び、第一声→選択への応答→終了の3ターンを実行。次の訪問では別の物語へ移った。第三者の立場は守ったが、返答が一般的な教訓へ寄る例は残る |
| 最後の選択 | 同じ先行状態の対照例で、約束を先送りする別れだけの返答から、直前の問いを説明して終える返答へ変化。中間の曖昧な返事まで常に解消したとはいえない |
| ねこ | 任意の非筆記・非発話の行動を実生成。別の再訪では書き文字に許可外の空白が入り却下・縮退した。有能な相棒としての複数場面受入は未完 |
| 失敗 | 通信/時間超過/出力不正から操作可能な短い終了へ縮退。実生成で再現した、子どもの選択とは別の原作台本への飛躍を修正 |
| 未知植物 | 実モデルは試食を促す選択肢を依然生成する。共通検証で拒否し、正常な拒否表現の誤却下は修正。修正前に通った自然な第一声の危険表現も回帰入力として拒否。通常の既知の食事は受理する |

保存された実出力の読み取りは、JSONのPASS数とは別に行う。
一部の比較は同じ保存状態・資料を用いた実モデルの対照例であり、乱数を固定した品質の統計的証明ではない。
初期main `58e06dd` との再現可能な合成比較では、同じ既読記憶の再登場と感想の継続指示の優先順位を検証した。

### 意図的な外部依存の差

- シナリオと既存GASは本番の各ディレクター・プロンプト・Worker/ブラウザ双方の出力検証・表示確定フックを直接使う。HTTPの所有者認証や実DOM描画そのものはシナリオ外。
- モデルだけは既存の検証用アカウント経路。検証用の回数制限を適用する。
- 非公開人物設定は同じv2パーサーを使う。GASは実行時に読み、本番は既存の1時間キャッシュと明示更新を使う。比較時は設定revisionとプロンプトの指紋を記録する。
- 実読書資料は認証済みの鮮度確認済み読取ミラー。Firestoreの現在文書を独立照合できたという主張はしない。合成試験では既読・撤回・帰属・複数NPCへの頻度制御を別に検証する。
- 記録圧縮は本番が次回参照する各NPCの直近3つの生成文を保ち、感想由来で本文を持たない診断行を数えない。完全な入力は各元結果行に残す。
- 公開CIのブラウザ試験は合成資料で第一声/選択/終了/再訪/失敗を検証。Android実機受入は未実施。

## PR #24: 双子の共有生成と追加受入

双子の人物設定は既存の非公開台帳を使用する。旧台本への通常の分岐を外し、
通常NPCと同じ文脈選定・モデル呼出し・履歴を使う。モデルは1回の生成で2人分を
`turns: [{speakerSlot, text}, ...]` として返す。保存済みの名前をアプリ側で付け、
1発話ずつ表示し、2番目の発話で選択肢を提示する。既存の個別タップと共通音声を維持する。
既存の名前ペアIDと設定を継承し、初回の生成失敗だけでは初対面を消費しない。
旧台本・シートはAIや人物設定が利用できない場合の縮退用に残す。

実Gemmaで2人の名乗り、2回の選択への応答、終了、同じ名前での再訪、
双子の訪問後の通常NPC、ねこの無言の反応を確認。未知の木の実では、
観察とそのままにする選択肢を確認した。ねこの手助けは架空場面の単発生成でも確認した。
前回の失敗5訪問は通信・提供元を区別できない記録3件、時間超過1件、書き文字の契約違反1件。
新しい検証ログは通信・HTTP・提供元応答・出力JSON・安全性拒否を分けて記録する。
前回の失敗出力を再検証し、ねこの横空白だけを除けば既存の字種と長さの制約で受理できることを確認。
安全性は双子の両発話と選択肢を検証する。感想への返答は具体化した例がある一方、一般論に戻る出力も観測した。
別途発生した保存セル上限はPR #23の履歴圧縮で対応済み。検証用の上限を76回に調整し、
1訪問の選択数に応じて必要な呼出し分だけ残数を確認する。

本番配信は担当者が同じmainコミットからWorker、Hostingの順に実施する。

`protocolRevision:scene-dialogue-v22-profile2`、`supportedNpcCount:12` を照合する。
レジストリは `1ommzez`、Hostingビルドは `20261118-forest-shared-twins-v24`。
プロトコルが食い違う間はAI生成が縮退するため、Workerの確認後にHostingを配信してページを再読込する。
実機では双子の各発話のタップ読み上げ、選択後の続き、閉じる操作、同じ名前での再訪、
通常NPCの会話とねこが読み上げられないことを確認する。

## Android v24 ログを受けた会話改善

- ねこの行動と書き文字は一つの会話欄に表示する。Workerとブラウザで共通の検証を行い、合計80字、書き文字48字と既存の文字種制限を適用する。文字は次の生成の直前履歴にも渡す。身振りだけの会話は引き続き可能。葉を筆記に使っただけで未知植物の試食と判定しない。
- モデル入力にNPCの正式表示名と残りの応答回数を渡す。既知の誤表記は、他の名前の一部や保存済みの双子名を変更しない範囲で正規化する。最後の返答は選んだ言葉や行動に応じ、その場で完結させる。
- 新着感想は引き続き直近の活動から選ぶ。長期記憶は14日より前の感想を、現在の既読状態と確認済み記憶・関連台本に基づいて選ぶ。ブラウザは最大2冊、各3件を取得し、表示と続きの生成に使う感想の現行文書を照合する。同じ本の長期記憶には訪問間隔と7日間の再使用間隔を適用する。検証GASは同期ミラーで同じ候補範囲と出力検証を使用する。
- 配信は Worker `forest-dialogue-v24-profile2` → Hosting `20261118-forest-dialogue-quality-v25` の順。正式Workerの `/health` で `protocolRevision=scene-dialogue-v24-profile2`、`registryRevision=1ommzez`、`configured=true` を確認する。

## Android v25 ログを受けた書字と会話の区切り

- ねこの文章を通常会話と同じ `text` に置き、`delivery:written` で表示と履歴に渡す。書字の場所や動作は生成しない。会話欄の固定補足は履歴に入れない。静かな身振りは `delivery:gesture` を使う。
- 会話を最大2返答で区切る。最後の候補はラベルとその場で返せる答えや反応を一緒に作る。画面にはラベルだけを出し、子どもが選んだ候補の着地点を最終の生成に渡す。実際に台本側で引き継ぎを予約した場合だけ、相手の表示名を `context.handoffTo` として生成に渡す。
- 検証専用GASは `node scripts/build-forest-persona-probe.mjs` で再生成する。同じ人物設定・本番ディレクター・出力検証を用い、1訪問あたり最大3モデル呼出し、1日76回の既存上限を適用する。
- 配信順はWorkerからHosting。正式Workerの `/health` で `forest-dialogue-v25-profile2`、`scene-dialogue-v25-profile2`、`registryRevision=1ommzez`、`configured=true` を確認してから、Hosting `20261118-forest-written-dialogue-v26` を配信する。

### 最後の選択と表示する返答を同時に作る

- 最後の `outcome` は次の生成への指示ではなく、選択されたときに表示できる返答本文。Workerとブラウザは本文のない候補や、安全性・文字種・話者の条件を満たさない候補を除く。候補がなくても、それまでの有効な返答は表示する。
- 選択時には元の既読・感想資料を照合してから、選ばれた返答をそのまま表示する。双子の最後の返答は指定された一人が話す。通常のAI訪問は最大2回の生成。登録済みの別NPCへの引き継ぎは同じ予約経路を使う。
- 同じ導入で対照する場合のみ、既存の統合検証キューでケースIDを `replay-opening` にし、同モードの先行結果IDと選択位置2つを指定できる。成功記録の導入を再利用し、続きの一回だけを実際に生成する。人物設定のリビジョンと双子の話者名が異なる場合は実行しない。

## 実Gemmaの配信前受入

本番配信は、候補コミットと人物設定を固定し、実Gemmaでの受入を完了してから判断する。
WorkerとHostingの本番環境を使わず、既存の検証専用GASとGemmaのテストアカウントで実行する。

1. 現行版の実際の入力・出力を採る。Androidログは発生箇所を特定する手掛かりに使い、原文がなければ検証GASの再現と区別する。
2. `node scripts/build-forest-persona-probe.mjs` で候補版を生成する。検証用Apps Scriptの `ForestPersonaProbe.gs` と候補版の一致を確認する。シナリオは本番の人物設定パーサー、選択と継続の処理、Workerとブラウザの出力検証を通す。
3. 人物設定の変更案も試す場合は、検証設定B27に `{npc,version,fields}` を入れる。 `fields` のキーは「人物設定」の項目名。ケースIDを `profile-preview:` で始めると、その検証だけに変更案が適用される。正本の反映は承認後に行い、公開リポジトリには本文を置かない。
4. 検証シナリオから全12 NPCの代表会話と、ねこの約20会話を登録する。初対面、雑談、既読記憶、本人の感想、別作品への感想、伝言の送受信、再訪を含める。既読ミラーは読み取り専用。該当する感想がないときは、ケースID `fictional-reflection`（人物設定プレビューの場合は `profile-preview:fictional-reflection`）にして、既読本IDと架空の感想を明示する。
5. `yondeneGemmaTestRunPendingNow` で最大5件ずつ実行する。選択位置は `[0,0]` などで指定し、実際の伝言選択は `["relay"]` を使う。一択だけが有効な回で指定した位置が消えた場合は、その情報も残る。先行結果IDから訪問状態を引き継げる。最終受入では第一声から新規生成し、導入を使い回さない。
6. 結果タブで、失敗や縮退も含む全会話を読む。技術評価では、モデル出力の受理・実際に表示された会話・完了を確認する。品質評価では口調、自然さ、意味、具体性、選択肢、終話、多様性、原作と既読資料の整合、安全性を記録する。候補の削除・差し替えは、選択肢の品質評価にも含める。
7. ねこの意味のあるAI会話は90%以上を暫定目安とし、重大な既知の回帰があれば配信を保留する。修正後は新しいrequestIdで必要なシナリオを再実行する。公開PRには匿名の集計と確認結果だけを記載する。実行ID、人物資料、実感想と入力全文は非公開台帳に保持する。

| 回帰ケース | 受入で確認する動作 |
| --- | --- |
| ねこの書字 | 読めるメッセージを第一声から表示する。筆記動作で終わらず、小1配当字以外はかなにする。読みやすい空白で正当な本文が落ちない。Gemmaが難しい漢字の読みを同じ出力に返した場合は、かなや句読点が変わっていないことも検証する |
| 最後の返答 | 選択に対応する具体的な答えを即時に表示する。かくれんぼの準備、次の質問、移動の約束で終わらない。通常会話のモデル呼出しは最大2回 |
| 伝言 | 送り手が子どもに渡す言葉を示し、受け手を次に自分で訪ねた時だけ、その中身に反応する。受け手を自動で呼んだり移動させたりしない |
| 文脈と多様性 | 既読・出典・感想帰属を守る。複数NPCで同じ感想を回覧したり、一人の関心を同じ日課に固定したりしない |
| 双子と安全性 | 名前と話者が一致し、各発話が前の発話に反応する。子どもの個人情報を尋ねたり、未知の植物の摂取を促したりしない |
