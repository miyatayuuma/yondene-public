# 本の森 NPC登録・整合性チェック

## 正本の分担

- **公開コード**：reading-shelf-firebase/forest-character-registry.mjs。
  NPC ID、表示名、森の初期位置と歩行、必要なスプライト、会話方式、
  読書の話題を扱う人物の別名、NPC同士の関係、標準音声、最低限の
  フォールバック設定を一か所で定義する。
- **非公開Sheets「人物設定」「根拠資料」**：原作を照合した詳しい
  人物像、台詞の癖、一人称、禁止表現。公開レジストリはこれらの代わりに
  ならない。未照合事項は推測で埋めない。
- **非公開Driveの画像manifest**：画像のファイルIDとポーズ補正。認証後に非公開フォルダ内の `manifest.json` を名前から検索する。公開コードにファイルIDは保存しない。
  公開コードに画像・本棚・読書記録・家庭の識別子を保存しない。
- **Firestore**：書籍の既読状態・感想の正本。
  キャラ登録の作業で書籍の状態、感想、評価を更新しない。

## 標準的な新キャラの追加

1. 原作と作品・版を同定し、利用予定の画像と権利を確認する。
2. 公開レジストリの roster に**1件だけ**加える。id は安定した英数字、
   mode:'ai'、sprite:'optional'（未取得なら森に出さない）、座標、歩行、
   aliases、related、標準 voice、簡潔な障害時台詞を指定する。
   aliases は承認済みの物語記憶の characters と対応させる。
3. Driveに2×2透過PNGを登録し、既存manifestの assets[id] に紐付ける。
   同時に非公開Sheetsの「人物設定」へ項目・確度・適用範囲と「根拠資料」の参照IDを登録する。
   契約と上限は [forest-profile-contract.md](forest-profile-contract.md) を参照。
4. 対象の既読本から承認済みの物語記憶・会話候補を用意する。
   新しいIDの追加だけでは台本の事実を捏造しない。
5. scripts/build-forest-voice-lab.mjs をNodeで実行して音声実験室を再生成し、
   forest-character-registry.test.mjs を含む全テストと
   Workerのドライランバンドルを実行し、PRをレビューする。
   実際に話しかけて初対面・通常・感想・他NPCの話題を確認する。
6. レジストリのキャラID・会話方式・画像要否が変わると、端末での次回起動時に
   古い非公開画像・人物設定キャッシュが自動的に無効化される。Driveの認証が
   再び必要になる場合がある。既存キャラの台帳内容だけを修正した場合は、
   「人物設定・会話を更新」で明示的に最新情報を読み込む。
7. GitHubのmainにマージした後、**Firebase HostingとCloudflare Workerの
   両方を別途デプロイ**する。新キャラがブラウザに出ても古いWorkerがIDを
   拒否することがある。Workerの /health に登録済みAI NPC数と
   registryRevision が含まれ、アプリは自分のレジストリと一致しなければ
   AIを起動せず、Worker更新の案内を表示する。個別の生成品質は実機で確認する。

通常NPCであれば、今後はIDを複数のコードファイルへ手作業で追加しない。
cat は無言、twins は専用の自動掛け合いであり、これらの特殊な挙動を
持つキャラは個別の設計・テストが必要。

## 回帰テストの重要点

- 一つのレジストリが描画・画像manifest・人物設定の許可ID・会話ディレクター・
  感想・日替わりテーマ・TTS・Workerすべてに届くこと。
- 既読と未読の境界、感想の原文と保護者要約の区別、森全体の話題重複防止。
- NPCの口調の違い、初対面と引継ぎ、Gemmaが利用できない場合の
  台帳フォールバックと個人情報を含まないエラー記録。
- スプライトが取得できない新NPCは無関係な仮画像で表示しない。
- ふたごの自動掛け合いと猫の非発話。
